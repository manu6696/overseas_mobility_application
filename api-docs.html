API backend per la gestione dei periodi di mobilità fuori sede.

Login utente

Autenticazione tramite header Authorization: Basic <credenziali> (email come username, password in chiaro). Se valide, il server genera e restituisce un JWT (validità 1 ora) da usare come Bearer token in tutte le richieste successive.

Responses

http://localhost:8080/api/v1/login

Recupera la lista delle application

Se nessuna di queste condizioni è soddisfatta, la richiesta viene rifiutata anche se autenticata.

Modifica lo stato o i dati di un'application

Endpoint unico multiuso, con logica differenziata in base al body e al ruolo:

  • Studente proprietario: può aggiornare i dati anagrafici/corsi.

  • Referent lecturer o Staff: possono impostare agreementApproved e lecturerReason.

  • Staff, con preDepartureCompleted: true: la richiesta viene accettata solo se lo stato attuale è Awaiting Agreement approval, agreementApproved è già true, e lo stato attuale NON è già Waiting for exam score approval. In caso di successo, lo stato passa a Mobility in progress e viene creato automaticamente un Transcript of Records vuoto (righe precompilate dai corsi dell'application, senza voti), con notifica broadcast via Socket.io.
